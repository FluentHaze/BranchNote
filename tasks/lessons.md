# 协作教训

## 下载入口的设备识别

- 错误模式：只检测到 macOS 就把 Apple Silicon 和 Intel 同时标为“当前设备”，混淆系统与芯片架构。
- 原因：未区分操作系统检测和架构检测，并低估了 Client Hints 可提供的能力。
- 预防：使用受支持的 architecture Client Hint 精确匹配；无信息、被拒绝或移动设备不显示架构推荐；不使用被冻结的 Intel User-Agent 字样推断 CPU。验证 arm、x86、无 API、拒绝及 iPad 场景。

## 官网下载与菜单的视觉验收

- 错误模式：限定说明段落宽度却漏设 margin-inline:auto，导致居中按钮下的提示偏左；语言导航直接沿用高对比表单选中块。
- 原因：只验证溢出和链接，未对照真实桌面截图检查对齐、密度与控件职责。
- 预防：下载按钮、元信息与辅助说明共用居中阅读列；对导航菜单单独检查桌面和窄屏截图、选中/悬停/焦点状态，图标统一库及线宽。

## 插入任务时保留原交付

- 错误模式：界面修复已有本地改动，但处理 Search Console 插入任务后，未完成验证与交付，用户无法确认进度。
- 预防：保留原任务清单和验证状态；插入工作结束后立即回到未完成项。只有真实可访问的部署或明确交付的本地预览才能标记完成，用户授权部署后应完成推送与线上核对。
