# BranchNote

一个离线使用的桌面分支发布记录工具。使用 React、TypeScript、Vite 和 Electron，界面参考 Apple 原生生产力工具：轻量侧栏、清晰表格、系统字体和克制的蓝色强调。

## 运行

需要 Node.js 22.16 或更高版本。

```sh
npm install
npm start
```

如果安装环境禁用了依赖安装脚本，首次运行桌面版前执行 `node node_modules/electron/install.js` 下载 Electron。

浏览器开发预览：

```sh
npm run dev
```

打开终端显示的本地地址（默认 `http://127.0.0.1:5180`）。浏览器预览数据与桌面版数据相互独立，可通过 JSON 备份迁移。浏览器版本不需要网络服务，但清理浏览器数据会删除其本地记录。

## 使用

1. 新建项目，或者在初始空白页面点击“体验示例工作台”。示例数据只用于体验，不会自动混入你的真实记录。
2. 新增分支，填写功能说明；部署到测试后，手动确认“已部署测试”。
3. 创建发布批次，填写各项目对应的目标发布分支。在列表中为分支选择批次。
4. 查看“待合并”，手动确认“已合入发布分支”。更换批次、项目或目标发布分支会清除未上线记录的合并确认。
5. 选中一条或多条记录，核对实际部署结果后确认上线。未提测或未合并会显示提醒；已上线记录可以撤销确认。
6. 全部记录上线或移出后，可以完成批次。未上线分支持续保留，不会自动加入下一批次。

发布状态仍由用户确认。“本地分支”支持读取本地仓库并执行经确认的 Git 合并，不自动推送或部署。归档项目保留全部记录，可在“项目管理”中取消归档。

快捷键：`⌘/Ctrl K` 搜索，`⌘/Ctrl N` 新增分支，`Esc` 关闭弹窗。

## 本地仓库与合并

此功能需要桌面应用，并在本机安装 Git。浏览器预览无法直接读取本地 Git 仓库。

1. 点击顶部“本地分支”，选择所属项目与仓库文件夹。也可以在编辑项目时先关联文件夹。
2. “导入分支记录”列出本地分支和最近提交说明。勾选需要记录的分支，可修改功能说明后导入；已存在的同名未上线记录不会重复导入。
3. “合并到发布分支”中选择本地目标发布分支，勾选功能分支，并填写备用的 `resolve/**` 分支名称。
4. 点击“预览合并清单”，核对仓库、当前分支、目标、来源分支与顺序后，再确认执行。

合并要求工作区干净，没有进行中的合并、变基或拣选。应用会在执行前再次核对分支提交，预览后发生变化时需要重新预览。目标分支和所选功能分支都必须已存在于本地；应用不自动拉取远程分支。

遇到冲突时，应用中止发布分支上本次未完成的合并，从发布分支创建所填写的 `resolve/**`，然后重新合入发生冲突的功能分支，并停下来展示冲突文件。**此前已经成功合入发布分支的提交会保留**，功能分支不会被改写。若当前目标本来就是 `resolve/**`，冲突直接留在该分支。

在开发工具中解决冲突、提交后，回到应用点击“已解决并提交，继续核对剩余合并”。接着在 `resolve/**` 合入剩余功能，最终使用这个分支进行发布。应用不会自动将 resolve 合回原发布分支，也不会推送或执行部署。Git 提交使用仓库现有的身份、合并策略和钩子配置。

合并执行结果会列出实际工作分支、已完成与待完成分支及 Git 输出；发布批次的合并状态仍需按实际目标确认，避免把 resolve 的结果误记为原发布分支的状态。

## TXT 导入

在工作台或“数据与设置”中选择 TXT 文件，先修正预览，再确认导入。例如：

```text
[主项目]
feature/login 登录页面体验优化
fix/profile 修复头像更新

项目：活动项目
feature/check-in 连续签到活动
```

分支与说明可以用制表符或多个空格分隔。没有 `/` 的分支名或无法识别的行保留为备注，需要在预览中补全或取消勾选。“已发”等状态保留原文，所有导入记录的状态均需重新确认。同一项目的同名未上线分支会阻止导入并提示修正。

## 本地数据与备份

桌面数据保存到 Electron 应用专用目录中的 `branchnote.json`：

- Windows：`%APPDATA%/branchnote/branchnote.json`（以 Electron 实际 userData 为准）
- macOS：`~/Library/Application Support/branchnote/branchnote.json`

操作成功后自动保存，写入失败时保留原界面或表单并显示错误。JSON 恢复会校验文件结构、预览摘要，并先将当前数据保存为同一目录中的 `before-restore-时间戳.json`。要恢复这份自动备份，在“数据与设置”中选择该文件。浏览器自动备份保存在本地存储的 `branchnote-before-restore-时间戳` 键中。

日常建议定期导出独立的 JSON 文件，避免系统或浏览器清理造成数据丢失。

## 验证与打包

```sh
npm test
npm run build
npm run pack:win
```

macOS 上运行 `npm run pack:mac` 生成 DMG。安装包输出到 `release/`。当前是未签名的开发版本；正式分发前需要配置对应平台的签名、公证及真实安装验证。macOS 打包和安装需要在 macOS 上执行验证。

第一版不包含账号、云同步、Git 平台连接和自动更新。
