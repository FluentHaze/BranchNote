# BranchNote

让每个分支都有着落。BranchNote 是面向 macOS 和 Windows 的桌面分支跟进工具：按项目整理功能分支，向测试、发布等目标提交合并请求，并跟踪合并状态，减少发布时的遗漏。

数据保存在本机，无需注册 BranchNote 账号。创建合并请求和同步状态需要连接你的 GitLab 或 GitHub。文中统一称为 MR，GitHub 对应 Pull Request（PR）。

## 安装与开始使用

在项目的 [Releases 页面](https://github.com/FluentHaze/BranchNote/releases)查看是否有适合你系统的安装包：Windows 使用 `.exe`，macOS 使用 `.dmg`。只有发布页实际提供的版本和平台才可下载；若没有安装包，当前还不能直接安装，请等待维护者提供发行版。

使用安装包不需要安装 Node.js、pnpm 或下载源码。本机需要安装 Git，并准备好已经克隆的项目仓库、提交身份和远程访问权限。应用沿用本机 Git 的认证方式。

macOS 安装包当前未配置签名和公证，可能出现系统安全提示。请确认安装包来源；若系统阻止打开，请联系维护者，不要关闭系统安全保护。

## 第一次提交 MR

1. 打开应用，点击侧栏“项目”旁的加号，创建项目并关联本地 Git 仓库。
2. 点击“从仓库添加分支”，挑选需要跟进的本地或远程功能分支。
3. 在“MR 目标”中选择仓库里已有的远程分支，例如测试分支或发布分支。可以添加多个目标并分别命名、设置区分色。
4. 在侧栏设置入口配置代码托管平台的域名、平台类型和访问令牌，并测试连接。Git 推送认证与平台令牌是两套配置。
5. 选择一条或多条功能分支，打开对应目标的提交操作。核对所选分支、目标、MR 标题和描述；标题默认取最后一个所选功能分支的提交说明，描述默认留空。
6. 提交时会先检查冲突。无冲突则继续推送源分支并创建 MR；有冲突则先提示，确认后在冲突处理分支中解决。
7. 成功后列表显示“MR 待合并”。打开 MR 到代码托管平台审核、合并，应用会继续同步其状态。

应用不会替你在平台上合并 MR，也不会自动部署。“已合并”表示 MR 已合入目标分支，不表示已经上线。

## 日常跟进

- **查找分支**：通过顶部搜索查找分支名或功能说明；列表支持按状态筛选。
- **批量提交**：勾选多条分支后统一提交，会汇总为一条 MR。
- **补充说明**：点击列表中的功能说明编辑改动备注，也可从每行“更多”菜单进入。
- **同步状态**：进入项目、返回窗口时刷新；前台按设置的周期自动同步，后台暂停。也可点击“刷新 MR”。周期可选 30 秒、1、2、5、10、15 分钟，默认 30 秒。
- **分支有新改动**：将对应“已合并”状态重置为待提交后再次提交。旧版测试状态的重置会同时重置发布记录；自定义目标分别维护状态。
- **整理项目**：归档保留历史；删除项目或分支记录只删除应用内台账，不删除仓库文件、真实 Git 分支或平台 MR。删除记录后重新添加不会恢复原状态。

## 冲突处理

完整的分支角色、冲突处理与后续发布步骤见 [推荐 Git 工作流](docs/git-workflow.md)。

提交前可单独点击“检查冲突”。检查使用当前已获取的远程跟踪引用，在独立临时仓库中执行，不切换当前仓库，也不会推送或创建 MR。需要最新分支时，请先更新远程引用。

发现冲突后，确认创建冲突处理分支再继续。默认名称为 `resolve`，应用会生成 `resolve/时间戳`；也可填写完整的新分支名。在面板中选择我方、对方、两边都要，或手动编辑内容。请逐文件确认最终代码，全部解决后继续提交；后续分支仍可能出现新的冲突。

单条无冲突分支直接作为 MR 源分支；多条分支会先整合，冲突则在指定分支处理。目标分支不会被直接合入或推送覆盖。提交前保持工作区干净，Git 身份及钩子沿用仓库配置。

未完成的冲突会话可在重启后继续；放弃会话会返回原分支并清理对应冲突处理分支。MR 创建后源分支会保留，供平台完成合并。

## 令牌与连接

在“设置与令牌”中按域名配置 GitLab / GitHub，私有部署平台请明确选择平台类型。令牌需要具备目标仓库的访问及创建 MR / PR 权限，具体权限范围遵循所属平台和组织要求。

令牌单独保存在本机，系统钥匙串可用时加密存储；不可用时界面会提示未加密状态，此时不要在共享设备上保存敏感令牌。令牌不随台账备份导出，换设备后需要重新填写。

## 本地数据与备份

在“数据与设置”中导出完整 JSON 备份，建议定期备份。恢复时先预览摘要；确认后会替换当前台账，并在替换前自动备份原数据。

默认数据目录：

| 系统 | 目录 |
| --- | --- |
| Windows | `%APPDATA%/branchnote/` |
| macOS | `~/Library/Application Support/branchnote/` |

台账文件为 `branchnote.json`，平台凭据另存于 `hosts.json`。实际目录以应用设置页显示为准。浏览器预览与桌面应用的数据相互独立。

## 常见问题

**找不到目标分支？** 目标必须是已有的远程分支。先在仓库中准备目标并更新远程引用，再回应用选择。

**推送失败？** 先检查本机 Git 认证、网络、仓库权限及钩子。推送失败时应用停止创建 MR，可在结果面板重试。

**没有令牌能提交吗？** 无法自动创建 MR 时可打开预填的创建页，在平台手动创建，再回应用重试关联记录。

**状态没有更新？** 点击“刷新 MR”，检查令牌和网络。同步失败保留原状态并显示错误；已合并 MR 停止轮询，已关闭 MR 会继续检查，以支持重新打开。

**离线能做什么？** 可查看、整理本地台账和备份；获取远程分支、推送、创建 MR 和同步平台状态需要网络。

**顶部标题栏为什么固定浅色？** 当前页面采用浅色界面，原生标题栏和系统对话框使用同样的主题，保持视觉一致。
