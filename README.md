# BranchNote

一个离线优先的桌面分支发布记录工具。使用 React、TypeScript、Vite 和 Electron，界面参考 Apple 原生生产力工具：轻量侧栏、清晰表格、系统字体和克制的蓝色强调。

## 运行

需要 Node.js 22.16 或更高版本。

```sh
npm install
npm start
```

如果安装环境禁用了依赖安装脚本，首次运行桌面版前执行 `node node_modules/electron/install.js` 下载 Electron。

浏览器开发预览：

```sh
npm run dev
```

打开终端显示的本地地址（默认 `http://127.0.0.1:5180`）。浏览器预览数据与桌面版数据相互独立，可通过 JSON 备份迁移。浏览器版本不需要网络服务，但清理浏览器数据会删除其本地记录。

## 使用

1. 新建项目，然后点击顶部“从仓库添加分支”，关联项目所在的仓库文件夹。侧边栏按项目组织：一个项目对应一个仓库文件夹，点侧边栏的项目名即可切换；打开应用时自动进入第一个项目。
2. 在分支选择器里挑选要跟进的分支。列表同时包含本地分支和全部远程分支（`origin/**`），点“更新分支”会执行 `git fetch --prune` 拉取最新状态。刚打开时列表是空的，只显示你主动选中的分支。**分支只能从仓库里挑选，不支持手填分支名**；弹窗顶部会显示这次读取的本地仓库路径、远程仓库地址（如 `origin · git@github.com:me/repo.git`）和当前 Git 提交身份（`user.name <user.email>`），方便确认仓库和身份是否选对。每条记录只有一处说明文字（分支备注），点分支名即可编辑；不再有单独的“分支标签”，避免同一个分支出现两套叫法。
3. 3. 列表里每个分支只跟两件事：**是否已合并测试分支**、**是否已合并发布分支**。
4. 主界面标题下方有一条醒目的**「本版本目标」栏**，显示当前的测试分支和发布分支。每个版本换分支名时点它直接改：可以选仓库里已有的分支，也可以填一个新名字（仓库里还没有时，合并会从起点分支自动创建，不用先去终端建分支）。
5. 每一行的「操作」列只放 **提交测试** 和 **提交发布** 两个按钮，点哪个就合哪个（目标沿用「本版本目标」栏记住的分支），点完立刻开跑，没有中间的选择页；编辑备注、删除记录收在右侧「⋯」菜单里，避免一行堆太多按钮。勾选多条后，列表上方的操作栏里也有同样两个按钮，一次把选中的分支全部合入。要临时换目标、新建分支名字或关掉推送，在合并弹窗里展开“高级选项”。
6. 合并成功后自动写回“发布分支”列，并记下目标与时间。
7. **分支后续有新提交时**，直接点该列的状态（已合并 → 未合并）即可重新标记为待合并，再提交一次；不需要删除或重建记录。重置「测试」时「发布」会一起回到待合并。
8. 合并遇到冲突时不用离开应用：每个文件点一下“采用我方 / 采用对方 / 两边都要”即可解决并自动跳到下一个，全部解决后自动提交、自动继续合并剩余分支，最终并回目标分支并推送。**冲突始终在临时分支（`resolve/时间戳`）上解决，功能分支从头到尾不会被修改，保持干净。**
9. **测试 / 发布分支受保护（平台禁止直接推送）时**：在「本版本目标」栏点开编辑，给对应分支勾上“受保护”（目标栏会出现锁标）。之后提交不再直接合并/推送目标分支，而是从目标分支拉出一条 `mr/*` 集成分支，功能合入集成分支、冲突也在它上面解决，完成后推送集成分支并自动打开预填好的 MR 创建页（GitLab / GitHub）；MR 在平台上合并后目标分支才更新。
10. 每行「⋯」菜单里的「删除记录」（以及勾选多条后操作栏里的「删除记录」）**只删除本应用里的跟进记录和合并状态，仓库里的真实分支不会被删除**；需要重新跟随时，随时可以“从仓库添加分支”再加回来。

归档项目保留全部记录，仍显示在侧边栏（标注“已归档”），在项目页点“归档/取消归档”即可切换。

快捷键：`⌘/Ctrl K` 搜索，`⌘/Ctrl N` 打开“从仓库添加分支”，`Esc` 关闭弹窗。

## 仓库、远程分支与提交

此功能需要桌面应用，并在本机安装 Git。浏览器预览无法直接读取本地 Git 仓库。

**读取与更新**

- 分支列表合并展示本地与远程：同名分支显示为一条，并标注 `本地`、`远程 origin`、领先/落后提交数；选择器里只列出短名，不加 `origin/` 前缀。
- “更新分支”逐个远程执行 `git fetch --prune`，只更新远程跟踪引用，不改动你的本地分支；结果会说明有多少分支出现新提交、新增或清理了多少个。
- 应用不会在后台自动联网；需要最新状态时手动点一次更新。远程认证失败时会提示先在终端完成一次 `git fetch` / `git push` 登录。

**提交到测试 / 发布分支**

提交入口按阶段分开：**提交测试** 写 `testMergedAt` / `testTarget`，**提交发布** 写 `releaseMergedAt` / `releaseTarget`，两列互不影响。哪个阶段由你点哪个按钮决定，应用不会替你默认选一个。

1. 目标分支可以直接选远程分支（例如 `origin/release/week-45`），不需要先 pull 到本地；也可以选本地分支，或从某个起点新建一个分支。
2. 发布分支默认优先本周的 `release/week-XX`，其次仓库默认分支。切到测试阶段时按 `test` / `qa` / `uat` / `dev` 等常见前缀自动匹配。
3. 以远程分支为目标时，应用会使用同名本地分支：不存在就按远程最新提交创建并建立跟踪；存在且落后就快进到远程最新；存在但已经分叉（本地有远程没有的提交）会拒绝执行，提示你先手动同步，避免把提交合进过期分支。
4. 点“提交测试”还是“提交发布”由你决定，不存在默认阶段。功能分支不会被改写，起点分支也不变。

**推送**

合并只会更新本地分支。目标是远程分支时默认勾选“完成后推送到 origin”，合并成功后直接推送；取消勾选则只改本地，结果面板仍保留“推送”按钮。推送失败（认证、网络、代理等）不会回滚已经完成的本地合并，处理完原因后可以直接重试，不必重新合并。

**冲突：在应用内解决**

遇到冲突时，应用中止目标分支上本次未完成的合并，从目标分支创建 `resolve/时间戳` 临时分支，重新合入发生冲突的功能分支并停在冲突解决面板。**此前已经成功合入目标分支的提交会保留**，功能分支不会被改写。

- 左侧列出所有冲突文件，右侧显示合并后的内容（带冲突标记），可以直接编辑。
- 想在自己熟悉的编辑器里改：点“用编辑器解决”，应用会把该文件交给系统默认编辑器（VS Code / Cursor 等）打开；保存后应用自动回读，内容实时同步到应用内的编辑区（以最后一次保存为准），你确认无误点「保存并标记已解决」即可，不会替你抢先提交中间版本。
- 也可以在应用内改：三个按钮都是一键生效——点“采用我方 / 采用对方”整份替换并标记已解决，点“两边都要”按三方合并（`git merge-file --union`）拼接后直接保存（双方改动都保留、公共内容只出现一次），随后自动跳到下一个冲突文件。二进制文件只能整份采用某一侧。
- 想微调就在右侧编辑后按“保存并标记已解决”；全部解决后应用自动提交并继续合并剩余分支，不需要再点“继续”。
- “保存并标记已解决”写入文件并 `git add`；全部解决后点“提交解决结果，继续合并”。
- 应用会自动合并剩余分支；都完成后把 `resolve/**` 并回目标分支、删除临时分支，再按需推送。
- “放弃本次合并”会 `merge --abort`、切回原分支并删除临时分支，已经合入的提交保留在目标分支上。

合并会话记录在仓库的 `.git/branchnote-merge.json` 中：中途关闭应用，重新打开提交弹窗会直接回到冲突面板继续处理。

**前置条件**：工作区干净，没有进行中的合并、变基或拣选；目标分支在合并期间发生变化会被拒绝。Git 提交使用仓库现有的身份、合并策略和钩子配置。

**受保护分支：只提交 MR，不直接合并**

测试 / 发布分支在平台上设置保护（禁止直接 push）时，直接合并会在推送一步被拒绝。给项目的目标分支勾上「受保护」后，提交流程自动变为：

1. 从目标分支最新提交拉出集成分支 `mr/<目标名>-<时间戳>`（本地和远程的目标分支都不碰）。
2. 功能分支合入集成分支，冲突在集成分支的 `resolve/*` 临时分支上解决——**功能分支和目标分支全程保持干净**。
3. 推送集成分支到远程，并自动打开预填好源分支 / 目标分支的 MR 创建页（按远程地址识别 GitLab / GitHub；其他平台会给出手动创建的提示）。
4. 台账按真正的目标分支记录，备注集成分支名；MR 在平台上被合并后，目标分支才真正更新。

MR 创建页只是预填链接，提交 MR 仍由你在平台上确认——不会代替你创建或合并 MR。

## 本地数据与备份

桌面数据保存到 Electron 应用专用目录中的 `branchnote.json`：

- Windows：`%APPDATA%/branchnote/branchnote.json`（以 Electron 实际 userData 为准）
- macOS：`~/Library/Application Support/branchnote/branchnote.json`

操作成功后自动保存，写入失败时保留原界面或表单并显示错误。JSON 恢复会校验文件结构、预览摘要，并先将当前数据保存为同一目录中的 `before-restore-时间戳.json`。要恢复这份自动备份，在“数据与设置”中选择该文件。浏览器自动备份保存在本地存储的 `branchnote-before-restore-时间戳` 键中。

日常建议定期导出独立的 JSON 文件，避免系统或浏览器清理造成数据丢失。

## 验证与打包

```sh
npm test
npm run build
npm run pack:win
```

macOS 上运行 `npm run pack:mac` 生成 DMG。安装包输出到 `release/`。当前是未签名的开发版本；正式分发前需要配置对应平台的签名、公证及真实安装验证。macOS 打包和安装需要在 macOS 上执行验证。

第一版不包含账号、云同步、Git 平台连接和自动更新。
