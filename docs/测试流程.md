# BranchNote 使用检查清单

适用于安装后的桌面应用体验检查，不需要搭建开发环境。日常操作见[使用指南](../README.md)。本清单是待执行步骤，不是已通过的测试报告。

涉及提交的检查请使用有权限的演示仓库及已有远程目标；创建 MR 会向该仓库推送源分支并调用平台接口。

## 1. 安装与启动

- 使用对应系统的安装包启动，确认窗口和文字显示正常。
- macOS 系统为深色时，应用标题栏仍与浅色页面一致；关闭再启动检查记录保持。
- 检查窄窗口、长项目名、长分支名、键盘 Tab 焦点与系统减少动态效果设置下的主要操作。

预期：普通用户无需 Node.js、pnpm 或源码；加载失败时有明确提示。

## 2. 创建项目与添加分支

1. 创建项目，关联本地 Git 仓库。
2. 打开“从仓库添加分支”，核对仓库路径、远程地址和提交身份。
3. 选择功能分支并添加，编辑功能说明或备注，尝试搜索和筛选。

预期：只展示用户选中的分支记录；不同项目各自维护清单。

## 3. 设置目标与平台连接

1. 为测试、发布或自定义目标选择已有远程分支。
2. 在设置中填写平台域名、类型和令牌，测试连接。
3. 尝试错误令牌，检查错误说明并重新填写。

预期：目标分别保存；界面不展示令牌原文。钥匙串不可用时明确提示未加密状态。Git 认证和平台令牌分别配置。

## 4. 单条与批量提交

1. 选择一条无冲突分支，打开提交面板并核对目标、标题、描述。
2. 提交后到平台查看 MR，确认源与目标正确。
3. 多选分支再次检查，确认批量内容汇总为一条 MR。

预期：单条无冲突直接使用功能分支作为源；多条先整合。目标分支不被应用直接合入，状态先显示待合并。推送失败时不继续创建 MR，可重试。

## 5. 冲突处理

1. 对有冲突的演示分支点击“检查冲突”。
2. 查看提示后取消，确认当前工作分支未切换。
3. 再次检查并确认创建冲突处理分支，逐文件选择版本或编辑内容。
4. 确认所有文件后继续；另一次演练中尝试放弃或关闭应用后恢复会话。

预期：检查本身不推送、不创建 MR；确认后才修改冲突处理分支。后续分支有冲突时继续提示；放弃后返回原分支。不要把“两边都要”等同于代码语义一定正确。

## 6. 平台状态跟进

1. 创建 MR 后点击“刷新 MR”。
2. 在平台关闭、重新打开或合并演示 MR，再回应用刷新。
3. 检查前台自动刷新周期与返回窗口后的同步。

预期：待合并、已关闭、已合并与平台一致；已合并记录平台时间。网络或令牌错误保留原状态并说明原因。合并不等于部署。

## 7. 备份与整理

1. 导出 JSON，在测试台账中恢复并核对摘要和记录。
2. 确认恢复前会备份原台账，令牌不会随台账导出或恢复。
3. 归档并恢复项目；删除演示分支记录，检查真实 Git 分支仍存在。

预期：删除只影响台账；备份恢复替换当前数据，换设备后需重新配置令牌。

## 反馈问题

记录应用版本、系统版本、操作步骤、期望与实际结果，可附不含敏感信息的截图。不要提交访问令牌、完整私有仓库内容或含凭据的远程地址。

已完成的验证及限制见[验证记录](validation.md)。维护者自动化检查见[维护说明](maintenance.md)。
